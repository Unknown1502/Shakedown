# Decisions

| # | Date | Decision | Why | Evidence |
|---|---|---|---|---|
| D1 | 2026-10-26 | The evaluator is SigmaHQ's own CI tool, `evtx-sigma-checker` v0.8.5 with `tests/thor.yml`. We do not write our own Sigma matcher. | It is ground-truth parity with the expert rule set, and a judge can rerun SigmaHQ's own process. A homemade matcher would need its own validation. | 470/470 parity (docs/DATASET_AUDIT.md) |
| D2 | 2026-10-26 | The checker runs only in a container with `--network none --read-only --cap-drop ALL --security-opt no-new-privileges --user 65534`, a memory and PID limit, and every input mounted `:ro`. The image is pinned by digest. | The binary has no public source, and rules may be model-written. | `tests/test_checker.py::test_docker_command_isolates_inputs` |
| D3 | 2026-10-26 | Staged rule files get index-based names; labels never become paths. | Model-supplied IDs are untrusted, so this blocks path traversal. | `shakedown/harness/checker.py` |
| D4 | 2026-10-26 | Datasets and the checker binary are downloaded at runtime from pinned versions with recorded sha256, never committed. | `regression_data` has no stated licence; the checker licence is unclear. | docs/DATASET_AUDIT.md |
| D5 | 2026-10-26 | Model IDs are selected from the live `/v1/models` listing, restricted to the `nvidia/` owner prefix. | The rules require an NVIDIA open model; no hard-coded IDs. | `tests/test_llm_select.py` |
| D6 | 2026-10-26 | Structured output tries the OpenAI-standard `json_schema` wrapper, then the bare-schema form shown in the Token Factory docs, and records which one worked. | The docs example differs from the OpenAI spec, so it must be tested live. | `shakedown/llm.py` |
| D7 | 2026-10-26 | The local Docker runner is a **development/fallback** path. It is not described as a Token Factory Sandbox. Token Factory Sandboxes (`contree-sdk` 0.3.6) is the target execution route once access is verified. | The track asks for code run in Token Factory; honesty about the execution boundary. | Phase 1 gate pending credentials |
| D8 | 2026-10-26 | Rule validation uses `sigma check` (sigma-cli 3.1.0). YAML is parsed with `yaml.safe_load` first, and staged files get convention-style names. | `sigma check` exits 0 on valid and 1 on invalid rules, but on malformed YAML it crashes with a raw traceback, and it flags non-conventional filenames as a HIGH issue. | Phase 1 validator spike (docs/STATUS.md) |
| D9 | 2026-10-27 | Evaluation runs in a **Nebius Token Factory Sandbox** (`shakedown/harness/sandbox.py`); the local Docker runner stays as an offline development path (`--runner local`). Every record carries an `evaluator` block saying which one ran. | Sandboxes access arrived on 2026-10-27; the track asks for code run in Token Factory. D7's condition is met. | `data/audit/sandbox_parity.json` (30/30 agree), `tests/test_sandbox.py` |
| D10 | 2026-10-27 | One immutable Sandbox image holds the checker, `thor.yml` and both benign baselines (extracted). Each evaluation uploads only candidate rules and attack EVTX files and starts a disposable VM with `networking.enabled=false`, running as uid 65534. | Uploading 976 MB of logs per run would be slow; baking them in is deterministic and the image holds no credentials. Inputs are sha256-verified before upload. | `tools/build_sandbox_image.py`, `data/audit/sandbox_image.json` |
| D11 | 2026-10-27 | The offline flag is sent by subclassing the SDK's `InstanceSpawnRequest` and registering the subclass in the client's operation table. `contree-sdk` stays pinned at 0.3.6. | SDK 0.3.6 has no `networking` option on `run()`, but the REST API accepts it. Verified from inside the VM: only `lo` exists and DNS fails, while a default run has `eth0` and resolves. A test checks the serialised request. | `tests/test_sandbox.py::test_offline_spawn_serialises_networking_off` |
| D12 | 2026-10-27 | The Sandbox image's Debian base is imported by tag, not by digest. | The importer returned HTTP 404 for the digest form. The result is pinned by image UUID afterwards. | `data/audit/sandbox_image.json` |
| D13 | 2026-10-27 | A checker run whose output exceeds the Sandbox capture limit (10 MiB) is an evaluator error, not a partial result. | Truncated output would undercount false positives. The loop receives the message "matched too many events" and repairs. | `shakedown/harness/sandbox.py::interpret_result` |
| D14 | 2026-10-27 | Retrieved web sources are screened for answer-bearing content (target rule id, known Sigma rule mirrors, a title matching the target rule, Sigma rule text). Policy `exclude` removes them and backfills from extra search results; policy `flag` keeps them and records the flag. Live runs and the demo recorder default to `exclude`; `run_pipeline` defaults to `flag`. An answer-bearing report URL is refused in `exclude` mode. | The live AdFind run and the recorded demos showed that a title search returns mirrors of the very rule being written; the PowerShell demo's top source carried its full detection list. Only the model-visible text changes; the batch benchmark never used research. | `tests/test_leakage_screening.py`, `tests/test_pipeline_leakage.py`, `evidence/leakage_audit/REPORT.md` |
| D15 | 2026-10-27 | Repair feedback refers to missed attack files as "attack sample N", never by file name. | SigmaHQ names attack samples after the rule id, so the real name told the model which published rule it was reproducing. Applies to Runs after the audit; Runs 1 to 9 are reported as run. | `tests/test_loop.py::test_repair_feedback_does_not_reveal_which_rule_an_attack_file_belongs_to` |
| D16 | 2026-10-27 | In leakage-controlled mode a `LeakGuard` refuses any model request that contains the target rule id or the attack file name, and checker error text is scrubbed of attack file names. | The source screen is a heuristic. The guard turns a miss into a visible failure instead of a quietly leaked run. | `tests/test_pipeline_leakage.py` |
| D17 | 2026-10-27 | The approved replay set is `demo/replay` (leakage-controlled runs only, failures included) and is the default folder. `demo/recorded` and `demo/recorded_local` are kept unchanged and labelled, not deleted. | The earlier recordings are the audit's evidence, and deleting them would hide the problem. The default must not show a contaminated run as a success. | `docs/DEMO_DECISION.md`, `demo/README.md` |
| D18 | 2026-10-27 | A plain "Run live" reads the scenario's first readable reference with Tavily. Custom report addresses are off by default (`--allow-custom-url`). | Without a typed URL a live run used no research at all, so Tavily did no work. Arbitrary addresses would let visitors point the paid tool anywhere. | `tests/test_live_source.py`, `tests/test_server_hosting.py` |
| D19 | 2026-10-27 | Spending caps persist (`--budget-file`) and there is a total cap (`--total-cap`); the client address is read from `X-Forwarded-For` only with `--trust-proxy`. | An in-memory counter reset on restart and a spoofable header could each defeat the caps. | `tests/test_budget_hosting.py`, `tests/test_server_hosting.py` |
| D20 | 2026-10-27 | Datasets are fetched by `tools/fetch_data.py` at pinned commit and release, with the sha256 of each release file pinned in the script. | The README told readers to fetch the data but gave no tool; a hash taken from the same release would not catch a swapped asset. | `tools/fetch_data.py` (run into a clean folder, identical to the existing data) |
| D21 | 2026-10-27 | Real-world evaluation reuses `evaluate_rule` and the runner interface through `shakedown.byo`; no second evaluation engine. EVTX only. | The evaluator already accepts arbitrary folders (verified); the checker only reads EVTX, so other formats would be advertised falsely. | `tests/test_byo.py`; a real run in `evidence/preflight_demo/` |
| D22 | 2026-10-27 | Supplied logs run on the local runner by default; the Sandbox runner needs `--i-understand-logs-leave-this-machine`. There is no repair step and no model call on supplied logs or SIEM results. | The Sandbox is an external service and repair shows events to the model; customer data must not leave without an explicit decision. | `tests/test_byo.py`, `tests/test_preflight_isolation.py` (a clean import loads no model-side module) |
| D23 | 2026-10-27 | Every assessment reports three independent statuses (rule validity, attack validation, environment preflight) and has no combined pass; the recommendation is one of four levels and never says deploy. | A lab match, a supplied-attack match and a clean SIEM window answer different questions and each can mislead alone. | `tests/test_assess.py` |
| D24 | 2026-10-27 | The Splunk connector calls only `authentication/current-context` and the search-job endpoints, allows a fixed set of SPL commands, requires explicit allowed indexes and a bounded window, refuses admin-class accounts by default, and adds an explicit log-source scope because the Sigma conversion adds none. It carried the label "implemented but not live-verified" until `tools/splunk_smoke.py` succeeded (it did on 2026-10-27; see D26). | Read-only has to be enforced by code, not asked for; missing telemetry must be distinguishable from zero matches; a mock is not proof. | `tests/test_splunk.py`, `tests/test_splunk_smoke.py` |
| D25 | 2026-10-27 | `pysigma-backend-splunk` 2.1.0 is a pinned dependency. | The Sigma CLI cannot convert to SPL without it. | `uv.lock` |
| D26 | 2026-10-27 | The Splunk connector is recorded as live-verified only after the project's smoke test and an 11-test live suite passed against a real Splunk Enterprise 10.6.1.1 container, and the label says "on a loopback test instance". | A mock is not proof. The instance, the events and the accounts are throwaway and simulated, so the claim is limited to that. | `evidence/splunk_live_verification/REPORT.md`, `tests/live/test_splunk_live.py` |
| D27 | 2026-10-27 | A Splunk role must be trimmed to exactly `search` after creation, and the connector warns about write-capable extras (`run_collect`, `edit_own_objects`, and similar). | The live run showed Splunk 10.6.1.1 adds five default capabilities to every new role, including one meant to have only `search`. | `tests/test_splunk_live_findings.py` |
